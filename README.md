# React Starter

Чат-бот на React, TypeScript и DeepSeek API.

## Ассистент разработчика — День 31

Раздел **Ассистент разработчика** отвечает на `/help` и `/help <вопрос>` по README, `docs`, API-описаниям и схемам. Текущая ветка, список локальных и известных удалённых веток, список файлов и сводка изменений поступают через MCP. Проверяется также соответствие всего ответа исходному вопросу. Ответы содержат проверенные цитаты; устаревший индекс требует обновления. Доступны DeepSeek и локальная Ollama.

```bash
npm run developer:index
npm run dev
```

CLI: `npm run developer:cli`, пример: `/help Как устроен проект?`. Для локальной модели: `npm run developer:cli -- --local`. Нужна Ollama с embedding-моделью; для облачных ответов — существующий `DEEPSEEK_API_KEY`. Индекс можно построить и кнопкой в интерфейсе. Архитектура, план, API и проверки: [docs/day-31.md](docs/day-31.md). Актуальная карта проекта: [docs/project-architecture.md](docs/project-architecture.md).

Кнопка **Открыть папку** подключает любой локальный проект: выберите каталог или вставьте путь, затем нажмите **Индексировать**. Проекты автоматически сохраняются в списке; у каждого свой индекс и история. Папка без Git поддерживается с явной отметкой MCP об отсутствии репозитория.

Внешний пример — iOS-проект **MyFamily**: [документация проекта](examples/myfamily/README.md), [подключение и проверка](docs/day-31-myfamily.md). Проект выбирается в интерфейсе или через `--project myfamily`; его RAG-индекс и Git-контекст изолированы от DeepChat.

## Сравнение формата ответа

Экран сравнивает два запроса с одним и тем же пользовательским prompt:

- без ограничений — только сообщение пользователя;
- с контролем — system-инструкция с явным форматом, `max_tokens: 120` и stop-последовательностью `<END>`.

Второй ответ специально выводится рядом с первым, чтобы увидеть, как параметры API и инструкции меняют результат.

## Разные способы решения

Экран «Способы решения» отправляет одну задачу несколькими способами:

- прямой ответ без дополнительных инструкций;
- пошаговое решение;
- генерация отдельного промпта и решение по нему;
- три независимых роли: аналитик, инженер и критик.

После этого председатель совета формирует единый итог на основе ответов всех трёх экспертов. Серверный endpoint для режима — `POST /api/reasoning`.

## Температура

Экран «Температура» отправляет один и тот же prompt пятью независимыми запросами с параметрами `temperature: 0`, `temperature: 0.7`, `temperature: 1.2`, `temperature: 1.7` и `temperature: 2.0`. Приложение показывает ответы рядом, чтобы пользователь самостоятельно сравнил их точность, креативность и разнообразие. Серверный endpoint для режима — `POST /api/temperature`.

## Сравнение моделей

Экран «Модели» отправляет один и тот же prompt трём моделям: небольшая `google/gemma-3-4b-it` через Hugging Face/DeepInfra и `deepseek-v4-flash` и `deepseek-v4-pro` через DeepSeek. Для каждого результата отображаются время ответа, количество токенов и стоимость. Автоматических выводов в приложении нет. Дефолтная математическая задача взята из benchmark-набора MATH, содержащего сложные задачи математических соревнований ([описание набора](https://huggingface.co/datasets/jeggers/competition_math), [исходный репозиторий](https://github.com/hendrycks/math)). Серверный endpoint для режима — `POST /api/models`.

## Агентный сервис

`AgentService` инкапсулирует обработку запроса: input policy → вызов LLM → output policy. Все агенты живут в одном Node/Express-процессе, поэтому создание большого количества агентов не запускает отдельные приложения. Конфигурации агентов и история диалогов сохраняются в локальный JSON-файл `data/agent-state.json` и загружаются после перезапуска. REST API доступен по префиксу `/api/agents`, а существующий чат работает через агента `default`.

Создание одного агента и массовое создание через CLI:

```bash
npm run agents:cli -- create --config agent-config.example.json
npm run agents:cli -- bulk --config agents-config.example.json
```

## Запуск

Оптимизация локальной Qwen для ответов по документации, сравнение параметров/prompt/квантования и замеры описаны в [docs/day-29.md](docs/day-29.md). Раздел приложения — **Оптимизация LLM**, CLI — `npm run llm:optimize:evaluate`.

Независимая оценка ответов через DeepSeek Pro: [docs/day-29-judge.md](docs/day-29-judge.md), CLI `npm run llm:optimize:review`. Агент проверяет смысл ответа по материалам, объясняет ошибки и пропуски; на странице можно оценить уже сохранённые ответы.

Нужен Node.js 24+ (планировщик использует встроенный SQLite).

```bash
npm install
npm run dev
```

После запуска откройте адрес из терминала (обычно `http://127.0.0.1:5173`). Планировщик запускается автоматически вместе с API.

Для локальной демонстрации собранного приложения используйте `npm start`, затем откройте `http://127.0.0.1:8787`. API и интерфейс доступны только на этом компьютере. Сводки формируются, пока сервер запущен и компьютер не спит; браузер можно закрыть. Задачи и результаты сохраняются в `data/scheduler.sqlite` и переживают перезапуск.

Перед запуском создайте `.env` на основе `.env.example` и вставьте свой ключ DeepSeek API:

```bash
cp .env.example .env
```

Ключ используется только сервером и не попадает в браузер.

Для запуска модели Hugging Face добавьте также `HUGGINGFACE_API_KEY`. Нужен токен с разрешением `Make calls to Inference Providers`; Hugging Face предоставляет бесплатный месячный лимит для экспериментов, после его исчерпания могут применяться платные тарифы.

## Структура

- `src/App.tsx` — интерфейс чата, сравнение ответов, моделей, температуры и способы решения задач.
- `src/styles.css` — глобальные стили и адаптивная верстка.
- `src/main.tsx` — точка входа React.
- `server/index.ts` — серверный прокси и SSE-поток от DeepSeek API.
- `data/agent-state.json` — локальное хранилище конфигураций агентов и истории диалогов (создаётся автоматически и не попадает в Git).
- `server/agent-service.ts` — изолированный сервис, сущность агента, registry и REST API.
- `server/agent-cli.ts` — неинтерактивная отправка конфигураций в сервис.
- `server/mcp-demo-server.ts` — локальный MCP-сервер с демонстрационным инструментом.
- `server/mcp-client.ts` — MCP-клиент, который подключается к серверу и выводит доступные инструменты.
- `vite.config.ts` — настройки Vite.
- `tsconfig.json` — строгие настройки TypeScript.

Для production-сборки используйте `npm run build`.
Для проверки типов используйте `npm run typecheck`.

## Приватная LLM в домашней сети — День 30

Mac выступает сервером, второй компьютер с Windows подключается через браузер. VPS и установка модели на Windows не нужны.

```bash
npm run llm:service
```

Сервис выводит сетевой адрес (например, `http://192.168.0.41:8788`). Откройте его на Windows и введите значение `PRIVATE_LLM_API_KEY` из созданного на Mac файла `data/private-llm.env`. Ollama остаётся на loopback; отдельный сервис предоставляет только локальный чат. Доступ по ключу, 12 запросов/мин, контекст 8192 токена, ответ до 1024 токенов. Одна генерация выполняется, до трёх запросов ждут в FIFO-очереди; чат показывает позицию и позволяет отменить ожидание.

HTTP API, проверка с Windows и результаты: [`docs/day-30.md`](docs/day-30.md). Автоматическая проверка: `npm run llm:service:check -- --url http://IP_МАКА:8788`; тесты: `npm run test:llm:service`.

Наглядная демонстрация очереди: `npm run llm:service:queue-demo -- --url http://IP_МАКА:8788`. Пять запросов одновременно: четыре получают ответы по очереди, пятый — HTTP 503 при заполнении. В терминале видны позиции, начало генерации и ответы; отчёт сохраняется в `docs/day-30-queue-results.json`.

Для записи видео запустите сервис в терминале Mac и отправьте вопрос с Windows: в этом терминале появятся время, IP клиента, первые 200 символов вопроса, позиция в очереди и завершение запроса. Чтобы скрыть текст вопросов, установите `PRIVATE_LLM_LOG_PROMPTS=0` в `data/private-llm.env` и перезапустите сервис.
