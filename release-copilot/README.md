# Release Copilot

Отдельное локальное AI-приложение для подготовки материалов релиза по реальному Git-репозиторию. Собственные React/Vite-интерфейс, Express-сервер, package.json, настройки и данные. DeepChat и его сервер не нужны; каталог можно вынести в отдельный репозиторий.

## Запуск

Нужны Node.js 22.18+ и Git. Для локального AI — работающая Ollama с моделью `qwen3.5:9b`.

```bash
cd release-copilot
npm ci
cp .env.example .env
ollama pull qwen3.5:9b
npm run build
npm start
# http://127.0.0.1:8796
```

Разработка: `npm run dev` — интерфейс на `http://127.0.0.1:5176`, API на `8796`. `PORT` в собственном `.env` меняет порт API. `npm test` и `npm run typecheck` проверяют приложение отдельно от DeepChat.

По умолчанию используется локальная Ollama. `RELEASE_LOCAL_MODEL`, `RELEASE_CONTEXT` и `RELEASE_MAX_TOKENS` настраивают модель и бюджет. Для облачного варианта задайте `DEEPSEEK_API_KEY` в собственном `.env`; в интерфейсе нужно явно выбрать DeepSeek. Код и найденные фрагменты тогда отправляются в DeepSeek.

## Как это работает

1. **Папка и диапазон.** Откройте локальный Git-проект, укажите номер релиза и два commit, тега или ветки. Номер версии — подпись отчёта: исходники, теги и настройки приложения не меняются.
2. **Фиксация исходников.** Сервис разрешает оба ref в SHA и читает разницу между этими двумя снимками. Переключать ветки не нужно. Незакоммиченные и неотслеживаемые файлы не включаются, сетевой fetch не выполняется.
3. **Контекст.** Документация и код предыдущей версии разбиваются на фрагменты. Лексический TF-IDF-поиск выбирает контекст для изменённых файлов. Это RAG без embedding-сервиса и без предварительной индексации.
4. **AI-анализ.** Каждый файл обрабатывается отдельно. Модель получает полный diff, полное содержимое файла и найденные фрагменты. Она предлагает сводку, пользовательскую заметку, конкретные потенциальные риски и план ручных проверок со ссылками на доказательства.
5. **Проверка ответа.** Обычный код проверяет JSON, существование источников и цитаты; для небольших замен прикладывает обе стороны diff. Отдельный вызов той же модели оценивает каждый пункт по его цитатам. После замечаний автор может исправиться, до трёх попыток. Модельная проверка может ошибаться.
6. **Связанные файлы.** Сервис просматривает оба Git-снимка и ищет прямые связи по именам типов, методов, свойств и относительным JS/TS-импортам. AI получает полные тексты связанных реализаций, неизменённых потребителей и тестов до и после изменения, сопоставляет поведение и переоценивает риски файлов. Межфайловые выводы и сценарии цитируют минимум два файла и изменённую строку; отдельный вызов модели проверяет смысл. Для снятия гипотезы о самом helper достаточно его собственной реализации; лишние цитаты не добавляются ради количества.
7. **Ручная проверка.** Вы просматриваете выводы и выполняете предложенные шаги, сохраняете результаты и заметки. Генерация сценария не означает его прохождение. Статус «Пакет готов» требует полного покрытия, подтверждения просмотра и прохождения всех проверок, включая межфайловые сценарии.
8. **Экспорт.** Доступны `release-notes.md`, `changelog.md`, `test-plan.md`, `readiness.json` и ZIP-архив с этими четырьмя файлами.

Одна очередь работает в фоне независимо от страницы браузера. Состояние, источники, модельные проверки и ручные результаты лежат в `data/release-runs/<id>/`. После перезапуска сервера прерванный анализ можно повторить с теми же SHA. Проекты хранятся в `data/projects.json`.

## Перенос результатов прежней версии

```bash
npm run import:deepchat -- --from ..
```

Команда копирует каталог проектов и историю релизов из прежнего DeepChat, сохраняя ID и абсолютные пути проектов. Исходники проектов и старые результаты остаются на месте; существующие запуски в новом приложении не перезаписываются. Ключи и прочие настройки старого `.env` не копируются. При переносе на другой компьютер заново откройте доступные локальные папки.

## Текущие границы

Это помощник подготовки релиза. Сборка приложения, запуск тестов проекта/Xcode, публикация в App Store/GitHub, сопоставление тикетов и правки документации пока не реализованы. MCP и другие разделы DeepChat не запускаются.

Изменённые текстовые файлы, diff и строки-доказательства читаются целиком, без прежних лимитов 30 файлов / 10 КБ / 4 КБ / 18 КБ. Корпус RAG предыдущей версии ограничен 400 документами/4 МБ. Закрытые пути, lock-файлы, бинарные объекты и неподдерживаемые форматы пропускаются. Локальная Ollama использует `RELEASE_CONTEXT`: если полный запрос не помещается, анализ файла завершится с понятной ошибкой, без обрезки. Для DeepSeek локальный бюджет Ollama не применяется; реальный размер контекста проверяет API провайдера. Ограничения показаны явно; неполный результат скачивается как черновик и не получает статус готового пакета.

Сервис слушает только loopback и рассчитан на доверенного локального оператора. Статус готовности относится к материалам, а не гарантирует корректность или публикацию приложения.

DeepSeek получает JSON Schema с точными ограничениями полей, а Ollama также использует её как формат генерации. При отказе повторная попытка включает предыдущий ответ и конкретные ошибки полей. Технические причины по каждой попытке сохраняются в `fileErrors[].diagnostics` файла `run.json`; служебные подсказки модели не выводятся в пользовательское сообщение. Проверка ссылок и независимая проверка смысла остаются обязательными.

## Проверка связей

Для новых запусков этап выполняется автоматически. Вкладка **Связи файлов** позволяет дополнить существующий запуск через `POST /api/releases/runs/:id/impact`, без повторной генерации отдельных файлов. Их ручные статусы и заметки сохраняются, подтверждение просмотра снимается, новые общие сценарии начинаются со статуса «Не проверено». Ошибка этапа делает покрытие частичным и блокирует готовность. Выводы и оценки гипотез входят в `changelog.md`, общие сценарии — в `test-plan.md`, состояние и проверки — в `readiness.json`.

Поиск связей эвристический, не заменяет граф компилятора. Проверяются прямые соседи изменённых файлов; неоднозначные имена не связываются наугад, динамические вызовы и некоторые языковые конструкции могут быть пропущены. Обнаруженные кандидаты не доказывают реальный вызов — это дополнительно оценивается по исходникам. Рассмотренные файлы, связи, цитаты и оценки (`confirmed`, `dismissed`, `uncertain`) сохраняются в `run.json`. Для облачного анализа взаимодействий предусмотрен отдельный бюджет ответа 16384 токена. Локальной модели может потребоваться увеличить `RELEASE_CONTEXT`; исходники не обрезаются.
