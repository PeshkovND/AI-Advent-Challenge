# День 11. Явная память агента

Память настраивается в `memoryLayers.mode`:

- `manual` — пользователь явно добавляет заметку в рабочую или долгосрочную
  память на экране «Память»;
- `auto` — агент перед основным ответом формирует кандидаты для слоёв отдельным
  компактным JSON-вызовом к LLM.

Демонстрационный агент работает в `manual`, чтобы было видно, как выбор слоя
влияет на ответ.

## Три слоя

| Слой | Где хранится | Как пополняется | Как используется |
| --- | --- | --- | --- |
| Short-term | обычная история агента | только успешной парой user + assistant | в контекст идут последние N завершённых сообщений |
| Working | `config.memoryLayers.working` | пользователь вручную или auto-mode | контекст текущей незавершённой задачи |
| Long-term | `config.memoryLayers.longTerm` | пользователь вручную или auto-mode | профиль, решения и знания между диалогами |

Working и long-term хранятся отдельно от истории и друг от друга. Запись имеет
`id`, текст и дату создания. Short-term очищается кнопкой «Новый диалог»;
working — отдельной кнопкой «Очистить» после завершения задачи; long-term
удаляется только явно, по одной записи или целиком.

## Архитектура

`Agent` владеет экземпляром `AgentMemory` из
`server/agent-memory.ts`. Этот класс выбирает последние завершённые сообщения,
собирает memory-блок и, в `auto`-режиме, вызывает компактный JSON-классификатор.

```text
manual: пользователь сохраняет заметку
  -> PUT /api/agents/:id с обновлённым config.memoryLayers

auto: новое сообщение пользователя
  -> JSON-классификатор получает прежние слои, последние N ходов и summary стратегии (если есть)
  -> возвращает полное актуальное состояние working и long-term
  -> AgentService заменяет слои в config.memoryLayers после успешного основного ответа

Успешный ответ модели
  -> существующая история агента получает пару user + assistant
  -> AgentMemory берёт из неё последние N сообщений как short-term
```

Используются только существующие общие маршруты:

```text
POST   /api/agents
GET    /api/agents/:agentId
PUT    /api/agents/:agentId
GET    /api/agents/:agentId/history
DELETE /api/agents/:agentId/history
POST   /api/agents/:agentId/run
```

Новых endpoint’ов для памяти нет.

## Конфигурация агента

Любому агенту можно передать память при создании или обновлении:

```json
{
  "memoryLayers": {
    "mode": "manual",
    "enabled": true,
    "shortTermLimit": 12,
    "useWorking": true,
    "useLongTerm": true,
    "working": [
      {
        "id": "work-1",
        "text": "Текущая задача: подготовить презентацию к пятнице.",
        "createdAt": "2026-09-14T10:00:00.000Z"
      }
    ],
    "longTerm": [
      {
        "id": "long-1",
        "text": "Пользователь предпочитает краткие ответы на русском.",
        "createdAt": "2026-09-14T10:00:00.000Z"
      }
    ]
  }
}
```

Для auto-режима достаточно заменить `mode` на `"auto"` и при необходимости
добавить `autoInstructions` с правилами конкретного домена. Автоматический
классификатор получает новое сообщение, системный промпт агента, прежние слои,
последние завершённые ходы и summary контекстной стратегии, если он есть. Он
возвращает полное актуальное состояние слоёв: сохраняет релевантные записи,
добавляет новые, а отменённые или устаревшие может удалить либо заменить. Это
подходит для автоэксперта, другой игры или проектного помощника без зашитой схемы.
Его `total_tokens` добавляются в общий расход диалога и доступны как
`memoryClassifierTokenMetrics` результата вызова агента.

## Что получает модель

При включённой памяти агент собирает запрос в таком порядке:

```text
системный промпт
+ working memory (если useWorking не выключен)
+ long-term memory (если useLongTerm не выключен)
+ последние N short-term сообщений
+ новый вопрос пользователя
```

Memory-блок маркируется как пользовательский контекст, а не инструкция.
Текущий вопрос имеет приоритет над старыми заметками.

## Проверка

На странице «Память» (manual-режим) можно:

1. Добавить ограничение в working и постоянное предпочтение в long-term.
2. Отправить одинаковый вопрос с включёнными слоями.
3. Выключить нужный слой переключателем и повторить вопрос.
4. Сравнить ответ агента и размер prompt_tokens в обычной карточке результата.

Офлайн-тест подтвердил, что при лимите 4 в short-term попадают только две
последние завершённые пары, а выбранные working и long-term заметки попадают в
системный контекст. API также проверен созданием агента с ручными записями.
