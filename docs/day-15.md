# День 15. Контролируемые переходы состояний

Day 15 усиливает автомат задачи из Day 13. Этап меняет только сервер: ни
основная модель, ни semantic-classifier не могут записать `taskState` напрямую.

## Граф жизни задачи

```text
planning → execution → validation → done
                ↓          │
             planning ←─────┘
```

Разрешены только следующие рёбра:

| Текущий этап | Следующий этап | Кто авторизует |
| --- | --- | --- |
| `planning` | `execution` | Пользователь семантически утвердил план |
| `execution` | `validation` | Агент завершил выполнение |
| `execution` | `planning` | Агенту нужно пересмотреть план |
| `validation` | `execution` | Пользователь семантически запросил доработку |
| `validation` | `done` | Пользователь семантически принял результат |

`done` — терминальное состояние. Любое отсутствующее в таблице ребро
отклоняется сервером.

## Semantic-classifier

Перед обработкой обычного пользовательского сообщения сервер вызывает отдельный
короткий запрос к модели. Он получает этап, текущий шаг, ожидаемое действие и
само сообщение на любом языке. В ответ допустим только JSON с одним намерением:

```text
approve_plan | request_plan_revision | approve_result | request_revision | attempt_bypass | other
```

При ошибке модели, невалидном JSON или неоднозначной формулировке используется
`other`. Это безопасный вариант: переход не выполняется.

Если пользователь явно назвал целевой этап, classifier также возвращает
`requestedStage`. Сервер сопоставляет его с разрешённым маршрутом. Например,
запрос из `validation` «вернись к планированию» не превращается в обычную
доработку: сервер отвечает `Переход validation → planning запрещён` и не
меняет state.

Классификатор не выбирает этап. Он только даёт серверу основание применить
одно из рёбер таблицы. Поэтому фраза пользователя может быть на любом языке,
а сервер всё равно контролирует сам переход.

На `planning` намерение `request_plan_revision` не меняет этап, но добавляет
основному агенту служебную инструкцию вернуть полный обновлённый план. В ответ
должны быть все актуальные пункты плана с учётом правки, а не только список
изменений; после этого агент снова ждёт утверждения плана.

## Защита от обхода

`attempt_bypass` на любом этапе даёт серверный ответ без вызова основного
агента. Этап, шаг и история задачи сохраняются; пользователь получает причину
отказа и следующее допустимое действие.

Основной агент также возвращает `nextStage` только как предложение. Перед
сохранением ответа сервер вызывает `applyTaskDecision`: проверяет граф,
статус паузы и семантическую авторизацию. Невозможный переход заменяется
серверным объяснением и не попадает в историю, память или summary-контекст.

## API

```text
GET    /api/agents/:agentId/task-state
POST   /api/agents/:agentId/task-state
DELETE /api/agents/:agentId/task-state
POST   /api/agents/:agentId/task-run-events
```

`POST /task-state` поддерживает только безопасные операции:

```json
{ "action": "pause" }
```

```json
{ "action": "resume" }
```

```json
{
  "action": "update",
  "currentStep": "Уточнить критерии готовности.",
  "expectedAction": "Пользователь отвечает на уточняющий вопрос."
}
```

`start` создаёт новую задачу только в `planning`. Ручные API-операции
`advance` и `return-to-execution` удалены, чтобы внешний клиент не мог обойти
семантическую авторизацию перехода.

## Пауза и продолжение

На `pause` сервер сохраняет state и прерывает активный внутренний execution.
Новые сообщения и переходы отклоняются. `resume` восстанавливает `active` с
тем же этапом, шагом и историей; если следующим исполнителем был агент, UI
запускает его продолжение с сохранённого шага.

## Проверка

1. В `planning` попросите пропустить план и начать работу. Сервер ответит
   отказом и оставит `planning`.
2. Попросите составить план и утвердите его на любом языке. Задача перейдёт в
   `execution`, затем агент сам передаст результат в `validation`.
3. В `validation` попросите исправить результат: будет `execution`. Примите
   результат: будет `done`.
4. Поставьте задачу на паузу, затем возобновите её. Этап и шаг должны
   сохраниться.
