# День 30 — локальная LLM как приватный сервис

Ветка `day-30`. Домашний Mac с установленной Ollama работает как сервер. Второй компьютер с Windows обращается к нему по HTTP в той же сети Wi-Fi/роутера. VPS, отдельная покупка GPU и установка Ollama на Windows не нужны.

```text
Windows: браузер / PowerShell
            │ HTTP + Bearer-ключ, домашняя сеть
            ▼
Mac: приватный Express-сервис, :8788
            │ HTTP, только 127.0.0.1
            ▼
Mac: Ollama, :11434 → qwen3.5:4b
```

## Запуск на Mac

Из корня проекта:

```bash
# Модель уже установлена на этом Mac. На новом сервере сначала:
ollama pull qwen3.5:4b
# Ollama должна быть запущена. Если приложение Ollama не работает:
ollama serve
```

В другом терминале:

```bash
npm run llm:service
```

Команда собирает отдельный интерфейс и запускает сервис. При первом старте создаёт `data/private-llm.env` с криптографически случайным ключом. Файл имеет права `0600`, исключён из Git и сохраняется между перезапусками. Повторный запуск сохраняет существующий ключ. Для создания настроек без запуска: `npm run llm:service:init`. После сборки можно запускать быстрее: `npm run llm:service:start`.

На этом Mac адрес во время проверки: **http://192.168.0.41:8788**. Адрес может измениться при переподключении к роутеру; актуальные адреса сервис выводит в терминале. Узнать Wi-Fi IP вручную: `ipconfig getifaddr en0`. `0.0.0.0` — адрес привязки сервера, в браузере используется конкретный IP Mac.

Сервис работает, пока запущен процесс и Mac не спит. Остановка — Ctrl+C в терминале сервиса. Если нужно временно удерживать Mac от сна, выполните в отдельном терминале `caffeinate -i`; Ctrl+C отменяет удержание. После перезагрузки снова запустите Ollama и сервис.

### Логи на Mac и запись видео

Сервис выводит логи запросов чата в тот терминал, где запущен `npm run llm:service` или `npm run llm:service:start`. После обновления кода перезапустите процесс. Для видео оставьте терминал Mac открытым, а с Windows отправьте заметный вопрос, например «Привет с Windows! Сколько будет 17 + 25?».

Пример формата (IP Windows и время будут вашими):

```text
[14:00:00] [#0001] [192.168.0.25] Получен POST /api/local-llm/chat
[14:00:00] [#0001] [192.168.0.25] Вопрос: "Привет с Windows! Сколько будет 17 + 25?"
[14:00:00] [#0001] [192.168.0.25] Начало генерации · qwen3.5:4b · ожидание 0 мс
[14:00:01] [#0001] [192.168.0.25] Завершён · HTTP 200 · 1000 мс
```

У каждого запроса один номер: по нему можно связать получение, ожидание в очереди, генерацию и завершение. Время — `AGENT_TIME_ZONE` из основного `.env`, по умолчанию Asia/Omsk. IP берётся из реального TCP-соединения, а не из `X-Forwarded-For`. При постановке в очередь выводятся позиции, при отмене — отключение клиента, при отказах — HTTP-код. Проверки статуса и загрузка страницы не засоряют лог запросов чата.

По умолчанию показываются первые 200 символов последнего вопроса, переносы и управляющие символы заменяются пробелами. `Authorization`, ключ доступа, cookies, параметры URL, полная история и текст ответа не выводятся. Логи идут в терминал, отдельный файл с ними не создаётся. Чтобы скрыть текст вопросов, добавьте `PRIVATE_LLM_LOG_PROMPTS=0` в `data/private-llm.env` и перезапустите сервис; остальные события останутся видны.

После добавления логов прошли 24 теста, включая связывание событий номером запроса, безопасный вывод текста, отсутствие ключа/URL/cookies в событиях, позиции очереди и продолжение работы при ошибке вывода логов.

## Подключение Windows

1. Подключите Windows к тому же роутеру, что и Mac.
2. Откройте в браузере `http://192.168.0.41:8788`.
3. На Mac откройте `data/private-llm.env`. Скопируйте **только значение после `PRIVATE_LLM_API_KEY=`** и вставьте в поле ключа на Windows.
4. Отправьте «Сколько будет 17 + 25?», затем «Прибавь 8 к предыдущему результату». Второй вопрос использует историю чата.

Ключ хранится в sessionStorage этой вкладки, история — в localStorage этого браузера. «Выйти» удаляет ключ из вкладки; «Очистить чат» удаляет сохранённую историю. История между двумя компьютерами не синхронизируется. Сервер не сохраняет тексты чатов в файлы и не отправляет их в облачную LLM. Ответы приходят потоком; генерацию можно остановить кнопкой.

Для HTTP API используется `Authorization: Bearer <ключ>`. Ключ не передаётся в URL и не включается в сборку интерфейса. Сервис использует обычный HTTP внутри доверенной домашней сети: транспорт не шифруется. Не пробрасывайте порт 8788 через роутер в интернет; для доступа за пределами дома потребуется отдельное защищённое соединение.

### Если страница не открывается

В PowerShell на Windows:

```powershell
Test-NetConnection 192.168.0.41 -Port 8788
```

`TcpTestSucceeded: True` означает, что TCP-порт доступен. Если `False`, проверьте адрес Mac, запущенный процесс, одну сеть и отсутствие гостевой Wi-Fi сети с изоляцией клиентов. Если macOS показывает запрос брандмауэра для Node, разрешите входящие соединения. При работающем TCP и ошибке 401 проверьте значение ключа, уберите пробелы и префикс `PRIVATE_LLM_API_KEY=`.

## HTTP API

| Метод | Путь | Результат |
|---|---|---|
| GET | `/` | Форма входа и приватный чат |
| GET | `/api/local-llm/status` | Модель, готовность, контекст и лимиты; требуется ключ |
| POST | `/api/local-llm/chat` | Чат; требуется ключ, NDJSON по умолчанию |

Тело запроса:

```json
{
  "messages": [
    { "role": "user", "content": "Сколько будет 17 + 25?" }
  ],
  "stream": false
}
```

`stream: false` возвращает один JSON с `message.content`, `done`, `contextInfo` и `queueInfo` (исходная позиция, время ожидания). `stream: true` или отсутствие параметра возвращает NDJSON: первая строка содержит `contextInfo`, последующие — события очереди и фрагменты Ollama. Событие `queueInfo.state: "queued"` сообщает текущую позицию, `"running"` — начало генерации и `waitedMs`. Для продолжения беседы клиент передаёт предыдущие пары user/assistant и новый вопрос. API не хранит историю между запросами. Модель и параметры генерации задаются сервером; клиент не может увеличить лимиты через тело запроса. `/status` также возвращает `queue: { active, waiting, maxSize }`.

Пример для PowerShell 5.1/7 на Windows:

```powershell
$serviceUrl = 'http://192.168.0.41:8788'
$secureKey = Read-Host 'Ключ с Mac' -AsSecureString
$credential = New-Object System.Net.NetworkCredential('', $secureKey)
$headers = @{ Authorization = "Bearer $($credential.Password)" }
Invoke-RestMethod "$serviceUrl/api/local-llm/status" -Headers $headers
$body = @{ messages = @(@{ role = 'user'; content = 'Привет! Ответь по-русски.' }); stream = $false } | ConvertTo-Json -Depth 5
$response = Invoke-RestMethod "$serviceUrl/api/local-llm/chat" -Method Post -Headers $headers -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body)) -TimeoutSec 195
$response.message.content
```

## Ограничения

Настройки редактируются в `data/private-llm.env`, затем сервис перезапускается. Переменные окружения процесса имеют приоритет над файлами настроек.

| Настройка | По умолчанию | Поведение |
|---|---|---|
| `PRIVATE_LLM_HOST` | `0.0.0.0` | Слушать IPv4 интерфейсы Mac; можно указать конкретный LAN IP |
| `PRIVATE_LLM_PORT` | `8788` | HTTP API и интерфейс на одном порту |
| `PRIVATE_LLM_API_KEY` | Случайные 32 байта, hex | Ключ всех API-запросов |
| `PRIVATE_LLM_RATE_LIMIT` | `12` | Общий бюджет попыток POST chat на ключ в фиксированном окне 60 сек. |
| `PRIVATE_LLM_CONTEXT` | `8192` | Передаётся в Ollama как `num_ctx`; допустимо до 32768 |
| `PRIVATE_LLM_MAX_TOKENS` | `1024` | Передаётся как `num_predict` |
| `PRIVATE_LLM_TIMEOUT_MS` | `120000` | Таймаут генерации 120 сек. |
| `PRIVATE_LLM_QUEUE_SIZE` | `3` | До трёх ожидающих запросов, дополнительно к одному активному; допустимо 0–10 |
| `PRIVATE_LLM_QUEUE_TIMEOUT_MS` | `60000` | Максимальное ожидание в очереди 60 сек., отдельно от генерации |
| `PRIVATE_LLM_LOG_PROMPTS` | `1` | Показывать первые 200 символов последнего вопроса в терминале; `0` скрывает текст |

`OLLAMA_BASE_URL` и `OLLAMA_CHAT_MODEL` берутся из окружения/основного `.env`: по умолчанию `http://127.0.0.1:11434` и `qwen3.5:4b`. В приватный конфиг можно вписать их отдельно. Ollama обязана находиться на loopback, облачные модели с тегом `cloud` отклоняются. Облачного fallback нет. Основное приложение и его планировщик запускать для этого сервиса не требуется.

Дополнительные ограничения:

- Одна генерация одновременно и ограниченная **FIFO-очередь**: до трёх запросов ожидают, каждый запускается после завершения предыдущего. Ожидание не запускает Ollama и не выделяет ещё один контекст модели. При заполнении очередь отклоняет новый запрос с **503**, `Retry-After: 2`. При `PRIVATE_LLM_QUEUE_SIZE=0` очередь отключается и занятый сервис сразу возвращает **409**. Обычный локальный чат Day 27 сохраняет режим без очереди.
- Чат показывает «Ожидание в очереди · позиция N» и обновляет позицию после продвижения или отмены других запросов. Кнопка «Отменить ожидание» удаляет запрос из очереди. Когда он доходит до модели, начинается генерация. Клиентский таймаут должен покрывать ожидание и генерацию (по умолчанию до 180 сек. суммарно, плюс сетевой запас). Ожидание ограничено 60 сек.; превышение даёт **504**. Для уже начавшегося NDJSON-потока HTTP остаётся 200, а ошибка приходит отдельной строкой `{ "error": "…", "status": 504 }`.
- Rate limit даёт **429**, `Retry-After` и заголовки `RateLimit-*`. Неверный ключ не расходует бюджет. Авторизованные попытки чата, включая невалидные, слишком большие и отклонённые при заполнении очереди, расходуют его. Постановка в очередь и её продвижение не создают дополнительных попыток. Статус модели не расходует этот бюджет. Бюджет хранится в памяти, сбрасывается после перезапуска.
- Тело запроса — до **1 МБ**, превышение даёт **413**. История — до 1000 сообщений с ролями user/assistant, последнее сообщение должно быть user.
- Для входа остаётся `контекст − максимум ответа − 512` = **6656** условных токенов. Оценка — UTF-8 байты + 64 на сообщение, с запасом, без точного токенизатора модели. Старые целые пары убираются скользящим окном; один слишком большой вопрос получает **400**. Полная видимая история остаётся в браузере.
- При обрыве клиентского соединения ожидающий запрос удаляется либо активный upstream отменяется. Таймаут генерации начинается после получения слота модели. Таймаут до начала потока возвращает **504**, ошибка Ollama — **502**; после начала потока ошибка приходит строкой NDJSON. После завершения, ошибки или отмены следующий ожидающий запрос получает слот. Очередь хранится в памяти и не переживает остановку сервиса.
- Ollama удерживает модель 60 сек. после запроса. Отдельный сервис не предоставляет эндпоинты облачных агентов, календаря, Telegram, планировщика или произвольного Ollama API. Интерфейс не загружает внешние шрифты, скрипты и изображения.

Ollama по умолчанию слушает loopback. Настройки `num_ctx`, `keep_alive` и особенности параллельной обработки описаны в [официальном FAQ](https://docs.ollama.com/faq), формат чата — в [документации `/api/chat`](https://docs.ollama.com/api/chat). При необходимости для Ollama можно включить `OLLAMA_NO_CLOUD=1`, как описано в FAQ; после изменения требуется её перезапуск.

### Наглядная демонстрация FIFO

```bash
npm run llm:service:queue-demo -- --url http://192.168.0.41:8788
```

Перед запуском дождитесь завершения других запросов. Если недавно запускалась полная проверка rate limit, дождитесь восстановления минутного бюджета. Скрипт отправляет пять запросов одновременно: первый выполняется, ещё три ожидают, пятый получает 503. В терминале видны позиции и продвижение; затем отправляется ещё один запрос для проверки восстановления. Облачные API не используются.

Фактический результат на Qwen 13 октября: ответы **21 → 22 → 23 → 24**, порядок запуска **1 → 2 → 3 → 4**, пятый запрос — **503**, проверочный шестой — **200**, ответ **26**. Исходные позиции: **0 / 1 / 2 / 3**; ожидание: **0 / 3109 / 3416 / 3709 мс**. Подробный отчёт: [`day-30-queue-results.json`](day-30-queue-results.json).

Для демонстрации в браузере откройте чат на Mac и Windows. На одном компьютере запросите подробную статью, а пока идёт генерация — отправьте вопрос со второго. Второй чат покажет позицию, дождётся завершения первого и автоматически начнёт получать ответ. Его можно отменить во время ожидания.

**13 октября 2026 года доступ с физически второго компьютера подтверждён пользователем:** на Windows открыта страница `http://192.168.0.41:8788`, выполнен вход по ключу и получен ответ в чате. Таким образом, проверена полная схема Windows → домашняя сеть → Mac → локальная LLM. Замеры времени и запуск PowerShell-скрипта на Windows этим подтверждением не заявляются.

### На втором компьютере с Windows

Скопируйте `scripts/check-private-llm.ps1` на Windows (репозиторий целиком для этого не нужен) и выполните из папки со скриптом:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\check-private-llm.ps1 -ServerUrl http://192.168.0.41:8788 -CheckRateLimit
```

`-ExecutionPolicy Bypass` действует на этот запуск PowerShell, не меняет системную настройку. Скрипт запрашивает ключ скрытым вводом, проверяет доступ, три последовательных запроса с историей, max context и, с флагом `-CheckRateLimit`, HTTP 429. Результат сохраняет в `day-30-windows-results.json` без ключа. PowerShell на текущем Mac отсутствует, поэтому этот скрипт здесь не исполнялся. Его можно запустить дополнительно, если нужен машинночитаемый отчёт с Windows для сдачи задания.

## Реализация

- `server/private-llm-server.ts` — отдельный сервер домашней сети.
- `server/private-llm-logger.ts` — логи запросов в терминале: время, IP, вопрос, очередь, генерация и завершение.
- `server/private-llm-app.ts` — изолированный HTTP API, bearer-авторизация, rate limit, размер тела и отдача интерфейса.
- `server/private-llm-config.ts` — настройки и создание локального ключа.
- `server/local-llm-router.ts` — общий чат с Ollama, NDJSON/JSON, контекст, события очереди, отмена и таймаут.
- `server/local-llm-queue.ts` — один активный слот, ограниченная FIFO-очередь и отмена/таймаут ожидания.
- `src/private-llm-main.tsx` — форма входа и существующий локальный чат в режиме дня 30.
- `server/private-llm-check.ts` — воспроизводимая проверка HTTP API.
- `server/private-llm-queue-demo.ts` — демонстрация позиций, продвижения и переполнения очереди на настоящей модели.
- `server/private-llm.test.ts` — проверки ограничений с временным локальным Ollama-стабом.
- `scripts/check-private-llm.ps1` — проверка с Windows.
