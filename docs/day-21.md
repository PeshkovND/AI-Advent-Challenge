# День 21 — индексация документов для RAG

Этот день добавляет локальный индекс учебного проекта. В корпус по умолчанию входят `README.md`, все файлы из `docs/`, `server/` и `src/`. Это осмысленный набор материалов о самом приложении: учебные статьи и исходный код. Markdown, TypeScript/TSX, JavaScript/CSS и PDF (при наличии `pdftotext`) приводятся к тексту до разбиения.

## Подготовка Ollama

Индексатор использует локальный Ollama API, поэтому данные и эмбеддинги не покидают компьютер. Установите Ollama, запустите его и загрузите embedding-модель:

```bash
ollama pull nomic-embed-text
```

По умолчанию ожидается `http://127.0.0.1:11434` и модель `nomic-embed-text`. При необходимости их можно поменять переменными `OLLAMA_BASE_URL` и `OLLAMA_EMBED_MODEL`.

## Построение и проверка индекса

```bash
npm run rag:index
npm run rag:stats
npm run rag:search -- "Как устроен локальный планировщик?"
npm run rag:demo
```

`rag:index` создаёт `data/rag-index.sqlite`. Файл не попадает в Git: это локальный артефакт, содержащий исходный текст чанков и их эмбеддинги. Для запуска одной стратегии можно передать `--strategy fixed` или `--strategy structured`; также доступны `--chunk-size` (число слов в чанке), `--overlap` (число общих слов) и `--database`.

`rag:demo` открывает интерактивное меню для демонстрации: показывает состояние индекса, выполняет поиск, выводит fixed и structured рядом для одного запроса и по явному подтверждению пересобирает embeddings.

## Состав индекса и метаданные

SQLite содержит три таблицы:

- `rag_index_runs` — время, модель, число документов и чанков, размерность вектора;
- `rag_document_chunks` — текст и метаданные чанка;
- `rag_embeddings` — вектор в JSON и его размерность.

У каждого чанка есть обязательные `source`, `title`, `section`, `chunk_id`, а также `strategy`, `ordinal` и `characterCount`. Поиск получает embedding запроса от той же модели и ранжирует все сохранённые чанки по cosine similarity.

## Сравнение стратегий

| Стратегия | Правило | Преимущество | Ограничение |
| --- | --- | --- | --- |
| `fixed` | 200 слов, overlap 40 слов | Ровный размер контекста, предсказуемое число слов | Может разделить мысль или Markdown-раздел |
| `structured` | Markdown по заголовкам, код по файлам; длинный раздел дополнительно делится на 200 слов с overlap 40 | Метаданные `section` соответствуют смысловой границе, выдачу легче объяснить | Размер чанков менее равномерен; крупный раздел всё равно дробится |

После первого запуска `npm run rag:index` напечатает фактическое число чанков отдельно для обеих стратегий, а `npm run rag:stats` — число документов, размерность эмбеддинга и имя модели. Это позволяет сравнивать результаты на одном и том же корпусе, а не на разных наборах данных.

### Контрольный прогон

На корпусе проекта из 54 документов с локальной моделью `nomic-embed-text` получились 768-мерные векторы. Контрольный запрос `SchedulerStore SQLite фоновые задачи` вернул первым раздел **«Хранение и worker»** из `docs/day-18.md` с cosine score `0.8203`.

| Стратегия | Чанков | Средний размер | Минимум | Максимум |
| --- | ---: | ---: | ---: | ---: |
| `fixed` | 437 | 1 836 символов | 246 | 3 539 |
| `structured` | 479 | 1 651 символ | 25 | 3 539 |

`structured` создаёт больше чанков, потому что сохраняет даже короткие заголовки и разделы отдельными смысловыми единицами. `fixed` более равномерен по размеру, но иногда начинает чанк в середине раздела. Метрики можно воспроизвести локально командой `npm run rag:index`.

## Проверка реализации

```bash
npm run test:rag
npm run typecheck
npm run build
```

Тесты проверяют фиксированный chunking и overlap, привязку структурных чанков к Markdown-заголовкам, round-trip SQLite с cosine-поиском и пакетный ответ Ollama через локальный mock-сервер.
