# Токены и контекст агентов

После каждого успешного запуска агент показывает три метрики:

- inputTokens — приблизительное число токенов только нового сообщения пользователя;
- promptTokens — точное число токенов полного промпта: системный промпт, история и новый вопрос;
- completionTokens — точное число токенов ответа модели из usage;
- conversationTokens — накопленная сумма totalTokens всех успешных API-вызовов.

inputTokens оценивается как количество символов нового сообщения, делённое на три. Это намеренно приблизительная учебная оценка: точный токенизатор зависит от модели. «Всего за диалог» показывает расход всего стека: каждый API-вызов добавляет свой totalTokens, включая повторно передаваемую историю.

Для totalTokens и completionTokens сервис требует usage от провайдера. OpenRouter возвращает usage с нативным токенизатором модели в обычном ответе и в финальном chunk потокового ответа: [Usage Accounting в OpenRouter](https://openrouter.ai/docs/cookbook/administration/usage-accounting).

## Контекст

История агента сохраняется в data/agent-state.json и при следующем запуске отправляется модели полностью. Локального обрезания или искусственного ограничения нет: реальный лимит контекста проверяет модель или провайдер. При переполнении API возвращает ошибку, а неуспешный обмен не добавляется в историю.

Кнопка «Очистить контекст» удаляет историю и накопленные метрики выбранного агента. На странице «Контекст и токены» кнопка «Удалить агента и начать заново» удаляет зарегистрированного context-demo, после чего приложение создаёт его заново с чистым состоянием.

## Что показывает страница

Страница «Контекст и токены» работает с обычным сохранённым агентом. Для каждого успешного запроса она показывает:

- приблизительный размер нового сообщения пользователя;
- точный размер полного промпта;
- накопленную сумму total_tokens всех успешных вызовов;
- точный completion_tokens ответа.

График строится по этим трём значениям: оценке нового сообщения и usage успешных API-вызовов. При переполнении вместо новых метрик показывается ошибка провайдера, а история остаётся в состоянии последнего успешного запроса.
