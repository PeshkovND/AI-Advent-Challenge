# Поддержка пользователей MyFamily

## Откуда взялось SSO

FlowDesk, корпоративный SSO, тарифы и связанные ошибки были вымышленным примером первоначальной реализации. К MyFamily они не относятся. Основная база поддержки теперь описывает MyFamily; FlowDesk сохранён отдельно в examples/support-flowdesk/ и не участвует в поиске. Прежние тикеты остаются в своём пространстве JSON-источника SQLite и не показываются пользователям MyFamily.

## Что взято из проекта

Проверена локальная копия MyFamily по commit fe9030e305306682dfea7a892c23b1a5a1a79dca. Исходники MyFamily не изменялись. База support/myfamily/knowledge/ содержит четыре документа, составленные по реальному коду и ранее подготовленной project/docs/: auth.md, profile.md, product.md и faq.md. В каждом указаны снимок и исходные файлы.

Подтверждённые факты:

- Вход начинается с телефона и запроса SMS. В конфигурации этого снимка — 10 символов ввода и countryCode "1".
- Код 1101 обозначает exceedLimitSMSCode. Число секунд извлекается из сообщения ошибки; постоянный лимит 60 секунд в коде не задан.
- После успешного запроса SignInViewModel отправляет .continue, но SignInCoordinator выполняет только print("succes"). Переход к подтверждению SMS не завершён.
- hasAuthorizedUser проверяет наличие credentials и срок действия. hasFilledProfile требует имя, фамилию и отображаемое имя.
- Home, Store и My Profile в проверенном снимке — TitleStubViewController; создание профиля и onboarding тоже содержат заглушки.

Это статическая проверка кода конкретного снимка. Она не подтверждает состояние другой сборки, доставку SMS, исправность backend или работу iOS-приложения. Для обновления знаний нужно повторно сверить исходники и пересобрать индекс через npm run support:index.

## Что демонстрационное

support/myfamily/crm.demo.json — источник тестовых пользователей и событий через настоящий MCP-сервер. Телефоны, токены и коды подтверждения в нём отсутствуют. Контекст содержит платформу, снимок сборки, этап входа, состояние сессии и заполненность профиля; для ошибки — код и ожидание из последнего события.

- Анна: ошибка 1101, в последней тестовой ошибке указано ожидание 60 секунд. Это не таймер и не правило для всех пользователей.
- Олег: тестовый запрос SMS успешен, переход к следующему экрану не произошёл. Доставка SMS и вход не подтверждены.
- Мария: профиль не заполнен, вместо редактора показан My Profile Screen.

В UI и MCP-источнике указано, что это демонстрационный контекст и backend не подключён. Ассистент получает название продукта и признак demo. Ответы и тикеты в сервисе поддержки сохраняются реально. Подключение к живым пользователям потребует отдельного источника подтверждённых диагностических данных.

## Сценарий для видео

1. Открыть поддержку MyFamily, выбрать Анну, создать тикет «Не могу запросить SMS» с описанием «При повторном запросе SMS вижу 1101 и сообщение подождать 60 секунд. Почему не работает авторизация и что делать?»; категория «Авторизация», код 1101.
2. Показать автоматический ответ, источники документации и MCP-контекст. Ассистент должен объяснить лимит и происхождение времени ожидания.
3. Уточнить в том же тикете: «А эти 60 секунд — постоянное ограничение для всех пользователей?». Документация не задаёт постоянное время; число относится к последней ошибке.
4. Выбрать Олега и его тикет, задать «Почему не работает авторизация?». Ответ должен учитывать успешный запрос SMS и известный незавершённый переход, без переноса ошибки 1101 от Анны.
5. Закрыть решённый тикет и перезагрузить страницу, показав сохранённую переписку и статус.

## Проверки

npm run test:support включает 21 тест: актуальный MCP-контекст, отсутствие полей FlowDesk и секретов, проверку владельца, разные ответы на один вопрос при разных контекстах, отделение снимка документации от backend и состав основной базы знаний. Вместе с тестами общего локального RAG, ассистента разработчика, code review, retrieval и grounding прошли 129/129. TypeScript и production-сборка проходят.

Для поддержки используется отдельная локальная модель Qwen 9B, уже установленная в проверенной среде. Настройка SUPPORT_LOCAL_MODEL меняет только поддержку, не модели других разделов. Для новой установки: ollama pull qwen3.5:9b. Маленькая Qwen 4B на пяти сценариях MyFamily прошла только проверку отказа на неизвестный сбой (1/5); четыре ожидаемых ответа заменяла отказами. Этот результат не скрыт и сохранён в day-33-myfamily-qwen4b-results.json.

npm run support:check проверяет пять сценариев настоящей локальной моделью и сохраняет docs/day-33-myfamily-local-results.json. После явного разрешения пользователя также выполнен npm run support:check -- --cloud: в DeepSeek переданы фрагменты подготовленной документации и синтетический контекст выбранных тикетов, без телефонов, токенов и SMS-кодов.

Реальная Qwen 9B прошла 5/5: лимит SMS, остановка после запроса SMS, заглушка профиля, общий FAQ и корректный отказ назвать неподтверждённый production-инцидент. Время отдельных проверок — 29,7–122,2 секунды. В интерфейсе создан тикет MyFamily, сохранён ответ Qwen 9B с шестью цитатами; с учётом истории и параллельной проверки ответ занял 167,8 секунды. Для видео ожидание локальной модели можно ускорить при монтаже.

Интерфейс по умолчанию использует локальную модель. Облачный вариант выбирается явно. Отчёт предыдущей Qwen 4B сохранён отдельно; прежний отказ также остался в истории тестового тикета.

## Удаление обращений

В шапке тикета доступна кнопка «Удалить тикет» с подтверждением. Удалённые обращения доступны через пункт «Удалённые» в фильтре списка; кнопка «Восстановить тикет» возвращает переписку и источники. Удаление останавливает активный ответ. После восстановления остановленное задание запускается только вручную. Эта возможность проверена вместе с остальной поддержкой: 25/25 тестов, включая реальные MCP/SQLite и отмену HTTP-генерации.

DeepSeek deepseek-v4-flash прошёл 5/5 тех же сценариев: лимит SMS (10,267 с), незавершённый переход (8,343 с), профиль-заглушка (7,094 с), FAQ (6,588 с), отказ на неизвестный production-инцидент (3,439 с). Четыре содержательных ответа прошли проверку цитат и смысловой поддержки; ответы по тикетам содержат и документацию, и MCP-контекст. Отчёт: [day-33-myfamily-cloud-results.json](day-33-myfamily-cloud-results.json). Это проверка прямого /ask без записи новых ответов в тикеты; дополнительный вопрос через UI не отправлялся.
