# День 19 — композиция MCP-инструментов

Day 19 расширяет существующий MCP Яндекс Календаря, а не создаёт отдельного агента или учебный сервер. Агент самостоятельно составляет цепочку инструментов из актуального каталога MCP; runtime не содержит списка имён или заранее прошитого pipeline.

## Демонстрационный сценарий

Пользователь пишет:

> Найди первое свободное окно на 60 минут в будние дни следующей недели с 10:00 до 18:00 и создай там событие «Фокус».

Агент выполняет вызовы последовательно:

```text
get_calendar_events
  → события из CalDAV REPORT calendar-query
find_free_calendar_slots
  → свободные интервалы, вычисленные из этих событий
create_calendar_event
  → новое событие, сохранённое в CalDAV через PUT
```

Первый инструмент получает внешние данные, второй обрабатывает именно переданный массив `events`, третий сохраняет результат в Яндекс Календарь. Это соответствует требованию задания без лишнего хранилища или второго orchestration-слоя.

`find_free_calendar_slots` — read-only MCP-инструмент. Он принимает период, IANA-часовой пояс, длительность, рабочие часы, дни недели и события из `get_calendar_events`; возвращает ограниченный список интервалов `{ startsAt, endsAt }`. Временные границы вычисляются в указанном часовом поясе, поэтому серверный часовой пояс не влияет на результат.

Событие создаётся только при явной просьбе пользователя. Вопрос «когда я свободен?» заканчивается на втором шаге и ничего не записывает в календарь. Если подходящих окон нет, запись также не выполняется.

## Автоматическая передача данных

MCP runtime передаёт структурированный результат каждого tool call модели как сообщение `tool`. Для зависимых операций его системная инструкция требует дождаться receipt предыдущего вызова, а затем использовать структурированные данные в аргументах следующего. Поэтому `events` не угадываются: они приходят из `get_calendar_events`, а `startsAt` и `endsAt` для `create_calendar_event` — из `find_free_calendar_slots`.

Под ответом календарного чата отображается фактическая `MCP-цепочка` с порядковыми номерами и статусом каждого вызова. Это trace сервера, а не утверждение модели.

## Проверка

Без внешнего календаря:

```bash
npm run test:calendar:slots
npm run typecheck
```

Тест проверяет передачу занятых интервалов в вычислитель, объединение пересекающихся событий, фильтрацию рабочих дней и точные границы свободных окон.

Для сквозной проверки с реальным CalDAV можно использовать существующий явно включаемый тест:

```bash
RUN_CALENDAR_PIPELINE_E2E=1 npm run test:mcp:pipeline:e2e
```

Он создаёт тестовое событие через автоматическую трёхшаговую цепочку, отдельно читает CalDAV для проверки и затем удаляет тестовое событие. Для Day 19 в интерфейсе достаточно выполнить демонстрационный запрос выше и убедиться, что trace содержит три успешных вызова в правильном порядке.
