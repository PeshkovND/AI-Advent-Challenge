# Сохранение контекста агентов

## Что сохраняется

Сервис хранит в `data/agent-state.json`:

- конфигурации созданных агентов;
- историю сообщений каждого агента;
- время создания агента.

Файл создаётся автоматически при первом запуске сервера и добавлен в `.gitignore`, потому что история может содержать пользовательские данные.

## Как работает запрос

Перед вызовом LLM сервис загружает историю выбранного агента и передаёт её в массив `messages` вместе с новым сообщением пользователя. После успешного ответа в историю добавляются два сообщения:

```text
user → запрос пользователя
assistant → ответ модели
```

Если ответ модели завершился ошибкой, неуспешный запрос в историю не записывается.

## Лимит контекста

Сервис не оценивает историю по длине текста и не удаляет старые сообщения по приблизительной формуле. При каждом запросе агент отправляет модели всю сохранённую историю.

Реальный лимит контекста проверяет модель или провайдер своим токенизатором. Если контекст переполнен, API возвращает ошибку, а неуспешный запрос не записывается в историю. Чтобы начать диалог заново, используйте `DELETE /api/agents/:id/history`.

## API контекста

```text
GET    /api/agents/:id/history
DELETE /api/agents/:id/history
```

`GET` возвращает сохранённые сообщения и их количество. `DELETE` очищает историю выбранного агента, но не удаляет самого агента и его конфигурацию.

На странице «Агенты» доступны обе операции: кнопка «Очистить контекст» удаляет только историю, а кнопка удаления в реестре удаляет пользовательского агента вместе с его историей. Встроенного агента `default` удалить нельзя, чтобы не ломать основной чат.

## Проверка после перезапуска

1. Откройте страницу «Агенты».
2. Создайте агента и отправьте ему сообщение, например: «Запомни, что меня зовут Никита».
3. Убедитесь, что в параметрах агента появился контекст из двух сообщений.
4. Перезапустите `npm run dev`.
5. Снова выберите агента и спросите: «Как меня зовут?».

Конфигурация агента и его история будут восстановлены из JSON-файла, поэтому модель получит предыдущие сообщения в новом запросе.
