# Текущая архитектура проекта

## Назначение

DeepChat — учебное приложение на React, TypeScript, Vite и Express. Оно объединяет облачный чат DeepSeek, AgentService, MCP, RAG, локальную Ollama и эксперименты с контекстом. Отдельный приватный сервис предоставляет локальную модель второму компьютеру в домашней сети.

## Структура проекта и точки входа

- `src/` — React-интерфейс. `src/main.tsx` запускает приложение, `src/App.tsx` управляет навигацией по разделам.
- `server/` — серверная логика TypeScript. `server/index.ts` запускает основной Express API на `127.0.0.1:8787`, подключает маршруты, AgentService и планировщик.
- `docs/` — документация проекта, описание заданий, API и результаты экспериментов. Документы `day-N.md` фиксируют историю развития соответствующего дня.
- `data/` — локальные SQLite-индексы, история агентов и результаты; каталог исключён из Git.
- `scripts/` — вспомогательные сценарии, включая проверку приватного сервиса с Windows.
- `vite.config.ts` — сборка основного веб-интерфейса и прокси API для разработки.
- `package.json` — зависимости, команды запуска, тестирования и индексации.

## Агент и MCP

`server/agent-service.ts` содержит AgentService, registry агентов, LlmClient, политики ввода/вывода и историю. `server/mcp-tool-runtime.ts` связывает агентов с календарём, планировщиком и Telegram через MCP. Для ассистента разработчика `server/project-mcp-server.ts` предоставляет отдельные инструменты чтения Git-контекста: текущую ветку, отдельный список локальных и известных удалённых веток, список отслеживаемых файлов и имена изменённых файлов. Список веток основан на локальных refs, без fetch; символический origin/HEAD исключается, усечение отмечается явно. `server/project-mcp-client.ts` вызывает их через MCP stdio при каждом вопросе.

## RAG и ассистент разработчика

Планировщик `server/developer-intent.ts` получает только вопрос. Простое перечисление или подсчёт Git-веток оформляются непосредственно из MCP: имена и счётчики остаются на сервере приложения, цитаты проверяются кодом. Для общих вопросов используется RAG и проверка всего ответа; список веток передаётся модели только при необходимости. Метка «Данные MCP · точные имена» отличает прямой вывод инструмента от синтезированного ответа.

`server/rag-indexer.ts` разбивает документы на чанки, получает эмбеддинги Ollama и сохраняет векторы и метаданные в SQLite. `server/rag-retrieval.ts` ищет через cosine similarity; также поддерживает query rewrite и реранкинг. `server/rag-grounding.ts` проверяет дословность цитат и смысловую поддержку утверждений. `server/local-rag-service.ts` содержит общий клиент local/cloud и адаптер доказательств для локальной модели.

Ассистент разработчика использует `server/developer-assistant.ts`, отдельный `data/developer-rag.sqlite` и manifest с отпечатком документации. В корпус входят README, `docs`, `project/docs` и API/схемы. Команда `/help` без вопроса объясняет структуру проекта, `/help <вопрос>` ищет ответ по документации и свежим результатам MCP. Индекс обновляется кнопкой в разделе «Ассистент разработчика» или командой `npm run developer:index`. Запросы обрабатываются маршрутом `POST /api/developer/help`. У каждого ответа есть цитаты документов или MCP-источников. Верификатор проверяет факты и выполнение исходного вопроса, чтобы текущая ветка не подменяла запрошенный список веток.

`server/developer-projects.ts` подключает любую локальную папку через диалог «Открыть папку» (`src/DeveloperFolderPicker.tsx`). `POST /api/developer/folders` показывает каталоги, `POST /api/developer/projects/open` сохраняет канонический путь и стабильный ID. Вопросы используют выбранный projectId. Индексы внешних папок лежат в `data/developer-projects/<hash-root>/`; история UI ограничена 20 ответами для каждого проекта. Папки без Git возвращают явный статус MCP `available: false`, сохраняя возможность RAG-ответов по README/docs.

## Запуск и проверка

Нужен Node.js 24+. `npm install` устанавливает зависимости. `npm run dev` запускает Vite и основной API вместе. `npm start` собирает приложение и запускает его на `http://127.0.0.1:8787`. Ключи хранятся в `.env`, пример настроек — `.env.example`.

Для локальных эмбеддингов нужна Ollama и модель `nomic-embed-text-v2-moe`; для локальных ответов — `qwen3.5:4b`. Облачные ответы используют `DEEPSEEK_API_KEY`. `npm run typecheck` проверяет TypeScript, `npm run build` собирает интерфейс, `npm run test:developer` проверяет ассистента разработчика.

## Автоматическое ревью PR

`server/code-review-context.ts` читает diff и файлы из неизменяемых Git blobs между merge-base и HEAD PR. Общие `documentFromText`, `chunkDocuments` и `publicProjectPath` используются для корпуса документации и кода merge-base. TF-IDF-поиск выбирает фрагменты отдельно для каждого изменённого файла; внешняя embedding-модель в CI не нужна. `server/code-review.ts` вызывает общий `modelClient` DeepSeek/Ollama, проверяет формат замечаний, реальные строки diff и дословные цитаты, формирует Markdown и JSON с покрытием. `server/code-review-cli.ts` доступен через `npm run review:pr`, воспроизводимое демо — `npm run review:demo`.

`.github/workflows/ai-code-review.yml` работает на `pull_request_target`, запускает reviewer и зависимости только из base SHA и читает head как данные. Workflow обновляет один комментарий, Job Summary и артефакт; устаревший отчёт не публикуется. Для запуска нужен repository secret `DEEPSEEK_API_KEY`, опционально variable `AI_REVIEW_MODEL`. Сценарий не меняет `/help`, MCP, индексы или состояние диалоговых агентов. Подключение и ограничения: [day-32.md](day-32.md).

## Приватный сервис

`server/private-llm-server.ts` запускает независимый сервис дня 30, `server/private-llm-app.ts` собирает его маршруты и защиту доступа. Команда `npm run llm:service` предоставляет локальный чат в домашней сети на порту 8788. Этот сервис не публикует маршруты `/api/developer` и не открывает Git-контекст проекта в сеть.
