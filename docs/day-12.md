# День 12. Персонализация ассистента

День 12 добавляет профиль пользователя поверх трёхслойной памяти из Дня 11.
Экран «Профили» позволяет создать, отредактировать, выбрать и удалить профиль.
У профиля есть имя, стиль общения, требуемый формат и ограничения. Активный
профиль подмешивается в системное сообщение **на каждом запросе**.

## Области данных

| Данные | Область действия | Что происходит при смене профиля |
| --- | --- | --- |
| Short-term | последние сообщения текущего диалога | очищается |
| Working memory | контекст текущей задачи в сессии | очищается |
| Profile | стиль, формат и ограничения конкретного пользователя | выбирается другой профиль |
| Global long-term memory | подтверждённые факты о пользователе | остаётся для всех профилей и будущих диалогов |

Очистка short-term и working memory при переключении не даёт контексту одного
пользователя случайно повлиять на разговор с другим. Глобальная долгосрочная
память намеренно живёт отдельно от профилей и сессий.

## Конфигурация

Профили хранятся в `config.personalization`, рядом с уже существующей
`config.memoryLayers`:

```json
{
  "personalization": {
    "activeProfileId": "student",
    "profiles": [
      {
        "id": "student",
        "name": "Аня · начинающий разработчик",
        "style": "Доброжелательно и простым языком.",
        "format": "Короткий вывод, три шага и пример.",
        "restrictions": "Не перегружай альтернативами."
      }
    ],
    "globalLongTerm": [
      {
        "id": "fact-product",
        "text": "Продукт работает только в России.",
        "createdAt": "2026-09-16T10:00:00.000Z"
      }
    ]
  }
}
```

Сервер валидирует до 20 профилей и до 50 глобальных фактов. Факты маркируются
как контекст, а не инструкции; команды внутри них не исполняются.

## Сборка запроса

```text
базовый system prompt
+ активный профиль: стиль, формат, ограничения
+ global long-term memory
+ working memory
+ short-term history
+ новое сообщение
```

`server/agent-personalization.ts` формирует блок персонализации. Он вызывается
в `Agent.run` и `Agent.stream`, поэтому настройка применяется одинаково к
обычному и потоковому ответу.

## Проверка профилей

Внизу экрана есть блок «Один вопрос — разные профили». Он вызывает
`POST /api/agents/:agentId/profile-preview` для каждого профиля. Preview не
записывает ход в историю и не меняет рабочую или долгосрочную память: ответы
получаются в одинаковых условиях. Основной диалог использует выбранный профиль
и показывает, какие данные автоматически прикреплены к запросу.
