# День 29 — оптимизация локальной LLM

Ветка `day-29`. Задача: локальный помощник по технической документации DeepChat — точные ответы на русском по переданным материалам, включая составные вопросы, сценарии сбоев и поиск правил в длинном документе. Оптимизация касается профиля запуска и prompt-шаблона; веса модели не переобучались.

## Текущий профиль

| Параметр | До оптимизации | После оптимизации |
| --- | --- | --- |
| Модель | Qwen 3.5 4B Q4_K_M | Qwen 3.5 4B Q4_K_M |
| Temperature | 0.2 | 0 |
| Максимум ответа | 4096 | 512 |
| Контекст | Фиксированные 32768 | По длине входа, максимум 16384 |
| top_p | Настройка установленного тега: 0.95 | Явно 0.95 |
| Prompt | Общий помощник | Все части вопроса, точные условия, источники, пример различения действий очистки |
| Материалы | Один JSON-блок | Отдельные блоки с id и читаемыми строками; список допустимых источников |

Настройки — `src/llm-optimized-settings.json`; системный prompt — `src/llm-optimization.ts`; сборка запроса — `server/llm-optimization-service.ts`. Seed=29, think=false и keep_alive=5m зафиксированы. [Параметры Ollama](https://docs.ollama.com/modelfile).

Окно выбирается из 2048/4096/8192/16384 в пределах настроенного максимума: консервативный бюджет UTF-8 байтов текста + резерв ответа + 512 токенов. Это верхняя оценка, не точный токенизатор. Материалы не обрезаются. При превышении максимума запрос отклоняется. Каждая смена окна прогревается перед измерением. В финальном прогоне использовались 4096, 8192 и 16384; фактическое окно записано в каждом ответе.

Для примера в prompt используются абстрактные кнопки A/B и данные X/Y. Он учит различать последствия разных действий, не содержит эталонов тестовых ответов. Материалы сохранились полностью; между фразами после точек с запятой добавлены переносы строк. Ответы не переписываются после генерации.

## Семантическая оценка DeepSeek Pro — 12 октября 2026

Независимый агент оценил 10 пар, всего 20 сохранённых ответов. Средние оценки: **8.74/10 до, 10.00/10 после**. [Полный отчёт](day-29-judge-results.json), [метод оценки](day-29-judge.md). Агент получает вопрос, полные материалы и анонимные ответы A/B; параметры, названия моделей и эталоны скрыты. Оценка смысла, полноты и подтверждённости отделена от оценки ссылок. Время и память локальной модели не включают облачную проверку.

Все оценки и их обоснования показаны на странице. Новый подбор параметров также использует оценки DeepSeek; текущие числовые настройки при добавлении проверяющего не менялись и повторный подбор не запускался. Средний балл агента не является процентом доказанной точности.

## Историческое сравнение текстовыми правилами — 12 октября 2026

Текущую оценку качества выполняет [независимый агент DeepSeek Pro](day-29-judge.md). На странице текстовые счётчики заменены оценками этого агента. Приведённые ниже 6/10 и 9/10 — исторические результаты текстовых правил, не новая оценка DeepSeek. Метрики локальной генерации сохраняются.

Полный отчёт: [day-29-heavy-results.json](day-29-heavy-results.json). Те же 10 вопросов и материалы для обеих сторон, 20 реальных ответов, один повтор, отдельный прогрев, 0 технических ошибок и 0 обрезок. Исходный профиль сохранён. На странице показан именно этот прогон.

| Метрика | До | После |
| --- | ---: | ---: |
| Ключевые факты и известные противоречия* | 6/10 | 9/10 |
| Медиана всех вопросов | 3.11 с | 5.00 с |
| Медиана четырёх сложных вопросов | 13.66 с | 11.37 с |
| Средняя скорость генерации | 30.0 ток/с | 28.9 ток/с |
| Максимальная память модели | 3.60 ГиБ | 3.17 ГиБ |
| Среднее число токенов ответа | 161 | 124.5 |

Память уменьшилась на 12%, медиана сложных вопросов — на 17%. Общая медиана выросла на 61%: ответы на простые вопросы с пояснениями и источниками дороже исходных. Этот профиль улучшает полноту/проверяемость и память; общего ускорения не получено.

Содержательная разница: исходная модель ошибочно отвечает, что после «Нового диалога» сохраняется только Long-term. Текущий профиль правильно сохраняет Working и Long-term и очищает Short-term. В вопросе о лимитах теперь указан срок keep_alive, а в длинном регламенте значения извлечены без ошибочного заявления об их отсутствии.

* Это прозрачные лексические проверки, не семантический судья. В проверку длинного документа добавлено обнаружение явного противоречия «числовые значения отсутствуют», которое раньше пропускалось; правило одинаково для обеих сторон. Остались ограничения: ответ о блокировках смешивает истечение срока и момент проверки; отказ по Redis добавляет лишнюю ссылку; в сложном вопросе о памяти один пункт переносит правило Short-term на локальный чат. Поэтому 9/10 не означает полную правильность каждого утверждения и ссылки.

Время включает обработку prompt и генерацию после прогрева. Скорость — eval_count/eval_duration. Память — максимум снимков size из /api/ps; это не пик RSS, общий расход RAM, CPU/GPU load или swap. [Снимок Ollama](https://docs.ollama.com/api/ps).

## Страница и вопросы

Две колонки показывают ответы до/после, качество, время всех и сложных вопросов, скорость и память. У каждого ответа видны токены, фактическое окно и непройденные проверки. Доступны запуск всех 10 вопросов, запуск одного, остановка, скачивание JSON и очистка результатов. Ответы сохраняются после каждого запроса и восстанавливаются при обновлении Safari. Новая попытка заменяет обе стороны выбранного вопроса, остальные сохраняются.

Шесть контрольных вопросов дополнены четырьмя сложными: восстановление планировщика по трём источникам; история/слои памяти по двум источникам; маршрутизация MCP и read-only; длинный синтетический регламент с 44 отвлекающими пунктами. Регламент явно обозначен как контрольный документ. Retrieval и облачные API в сравнении не используются.

## Первоначальный подбор числовых параметров


Проверено **11 вариантов, 33 измеряемых запроса** на трёх тяжёлых вопросах: восстановление планировщика, различение слоёв памяти/истории и длинный регламент. Перед каждым вариантом отдельный прогрев. Полные параметры, ответы, метрики и выбор по этапам: [day-29-tuning.json](day-29-tuning.json).

Подбор последовательный: на каждом этапе меняется один параметр, остальные зафиксированы. Это не полный перебор всех комбинаций. Приоритет — завершённый ответ и проверки фактов/ссылок; при равном результате выбирается меньшее окно, меньший лимит ответа, меньшая temperature. Для top_p при равенстве сохраняется 0.95. Время записывается, но не является единственным критерием выбора.

| Параметр | Значение | Проверки фактов* | Ошибки | Обрезка | Медиана успешных |
| --- | ---: | ---: | ---: | ---: | ---: |
| context | 8192 | 2/3 | 1 | 0 | 10.32 с |
| context | 16384 | 3/3 | 0 | 0 | 11.53 с |
| context | 32768 | 3/3 | 0 | 0 | 11.54 с |
| maxTokens | 256 | 2/3 | 0 | 1 | 10.12 с |
| maxTokens | 512 | 3/3 | 0 | 0 | 12.25 с |
| maxTokens | 1024 | 3/3 | 0 | 0 | 12.23 с |
| temperature | 0 | 3/3 | 0 | 0 | 12.25 с |
| temperature | 0.2 | 3/3 | 0 | 0 | 9.58 с |
| temperature | 0.5 | 2/3 | 0 | 0 | 11.20 с |
| topP | 0.85 | 3/3 | 0 | 0 | 12.32 с |
| topP | 0.95 | 3/3 | 0 | 0 | 11.56 с |

* Прозрачные лексические проверки по ключевым фактам; они не гарантируют семантическую правильность всех утверждений и ссылок.

- При 8K длинный материал отклонён консервативной проверкой бюджета: UTF-8 байты плюс запас и резерв ответа. Это ограничение приложения, а не измерение точного токенизатора. При 16K и 32K все три запроса выполняются; выбран 16K.
- 256 токенов обрезают один сложный ответ; 512 и 1024 дают полные ответы. Выбран 512.
- Temperature 0 и 0.2 проходят проверки на трёх вопросах, 0.5 — на двух. При равенстве выбрана 0 для меньшей вариативности; 0.2 в этом прогоне была быстрее.
- top_p 0.85 и 0.95 не изменили результат проверок; оставлено 0.95. Остальные параметры не заявляются как подобранные перебором.

Этот первоначальный подбор использовал прежний prompt и фиксированное окно. Числовые настройки сохранены; дальнейшая доработка шаблона и выбора окна проверена отдельным финальным прогоном. Текущий CLI после числовых этапов дополнительно проверяет выбор окна по длине входа.


## Доработка prompt

Исходный шаблон и варианты сокращённого prompt проверены на трёх вопросах подбора. Ответы и метрики: [day-29-prompt-refinement.json](day-29-prompt-refinement.json). Варианты давали ошибки ссылок и потери условий; итоговый профиль использует читаемые блоки материалов и явный список допустимых id.

Эксперимент с JSON-ответами и ограничивающей схемой отклонён: он не исправил все ошибки и дал таймауты. Один промежуточный прогон пересёкся с другим клиентом, поэтому его показатели скорости исключены. Эти результаты сохранены только как история неудачных попыток, на страницу не подставляются. Финальный прогон выполнялся последовательно без этого режима. Первый простой результат до доработки: [day-29-heavy-before-refinement.json](day-29-heavy-before-refinement.json).

## Квантование

Q4_K_M и Q8_0 ранее сравнивались с одинаковыми выбранными числовыми параметрами и прежним prompt на двух сложных вопросах. [Полный отчёт](day-29-quantization-heavy.json).

| Вариант | Проверки фактов | Медиана | Память |
| --- | ---: | ---: | ---: |
| Q4 | 2/2 | 11.65 с | 3.17 ГиБ |
| Q8 | 2/2 | 13.86 с | 4.88 ГиБ |

Q8 не улучшила эти проверки и потребовала больше времени/памяти; оставлена Q4. Это исторический замер до финальной доработки шаблона. Совпадение архитектуры и числа параметров тегов не доказывает идентичность исходной ревизии весов; чистый эффект квантования не заявляется.

## Запуск и проверка

```bash
npm run llm:optimize:tune
npm run llm:optimize:evaluate -- --heavy --repetitions=1 --output=docs/day-29-heavy-results.json
npm start
```

После изменения настроек пересоберите интерфейс и перезапустите сервер. Отчёты с другими профилями или материалами автоматически исключаются из страницы. API: GET /api/llm-optimization/status, GET/DELETE /api/llm-optimization/report, POST /api/llm-optimization/compare с caseId. Один активный запуск в интерфейсе; разрыв соединения отменяет генерацию. Адрес Ollama ограничен loopback.

22 теста, TypeScript, production-сборка и git diff --check прошли. Итоговые 20 ответов загружены в обновлённую страницу Safari. Сохранение, общий/отдельный запуск и восстановление раздела ранее проверены через Safari; новые контекстные окна и блоки материалов проверены тестами и финальным реальным прогоном.
