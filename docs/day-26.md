# День 26 — запуск локальной LLM

Модель по умолчанию: `qwen3.5:4b`, Ollama, квантование Q4_K_M. Машина: MacBook Pro, M1 Pro (8 CPU / 14 GPU), 16 ГБ общей памяти.

## Запуск

```bash
ollama pull qwen3.5:4b
# Если Ollama ещё не запущен:
ollama serve
```

В другом терминале:

```bash
npm run llm:local:demo
ollama ps
```

CLI-запрос:

```bash
ollama run qwen3.5:4b --think=false --keepalive 60s "Сколько будет 17 + 25?"
ollama stop qwen3.5:4b
```

HTTP API используется демонстрацией напрямую: `POST http://127.0.0.1:11434/api/chat`. API-ключи облачных провайдеров не нужны. Загрузка весов требует интернета; генерация выполняется локально. Скрипт разрешает только loopback-адрес Ollama.

## Вопросы из консоли

```bash
npm run llm:local:chat
```

После приглашения `Вы:` введите свой вопрос и нажмите Enter. Можно последовательно задать три вопроса любой сложности. Выход: `/exit` или Ctrl+D. Вопросы отправляются независимо, без истории. После выхода ответы и метрики сохраняются в `data/day-26-console-results.json`. Для 9B: `OLLAMA_CHAT_MODEL=qwen3.5:9b npm run llm:local:chat`.

Автоматический прогон заранее заданных вопросов остаётся в `npm run llm:local:demo`.

## Ограничение ресурсов

Текущие настройки: контекст — 32768 токенов; максимум ответа — 4096 токенов; `think: false`; `keep_alive: "60s"`. Три запроса идут последовательно. Настройки относятся к этому скрипту и не меняют другие приложения. Для нескольких одновременно запущенных клиентов ограничение параллелизма нужно задавать отдельно на сервере Ollama.

Генерация может активно использовать GPU. Автоматическая выгрузка освобождает память модели после простоя. При необходимости немедленного освобождения: `ollama stop qwen3.5:4b`.

## Проверка

Скрипт выполняет арифметический запрос, объяснение процессов/потоков и задачу на TypeScript. Выводит ответы, время и скорость, проверяет непустой ответ и отсутствие обрезки лимитом. Результаты сохраняются в `data/day-26-results.json`; можно передать другой путь:

```bash
npm run llm:local:demo -- docs/day-26-results.json
```

## Фактический результат — 8 октября 2026

Проверены обе модели Q4_K_M через локальный HTTP API; каждая ответила на все три запроса, без обрезки.

| Модель | Память Ollama | Размещение | Простой | Средний | Сложный | Скорость среднего / сложного |
| --- | --- | --- | --- | --- | --- | --- |
| Qwen3.5 9B | 6,1 ГБ | 100% GPU | 13,6 с | 13,9 с | 47,2 с | 20,0 / 19,2 токенов/с |
| Qwen3.5 4B | 3,1 ГБ | 100% GPU | 2,2 с | 7,8 с | 28,8 с | 34,0 / 32,7 токенов/с |

Первый запрос включает загрузку модели; эти времена не являются чистым сравнением скорости генерации. Замеры сделаны последовательно на машине с открытыми приложениями.

До 9B swap был нулевой, при её работе вырос примерно до 1,7 ГБ. После выгрузки 9B и запуска 4B swap оставался около 1,67 ГБ: macOS не обязана сразу возвращать страницы из swap. Нового роста во время прогона 4B не наблюдалось. Показатель memory_pressure вырос с 19% до 44%; это диагностический показатель системы, а не количество свободной RAM.

Поэтому 4B выбрана для повседневной работы; 9B установлена для более сложных задач. Все модели не сравнивались, поэтому абсолютное первенство по качеству не заявляется.

Арифметика: обе ответили `42`. Обе функции TypeScript используют Set, сохраняют первое вхождение и порядок, имеют ожидаемую сложность O(n). В объяснениях процессов/потоков есть упрощения: потоки могут участвовать в межпроцессном взаимодействии, а отдельные регистры и стек — не все свойства потока. Ограничение в 150 слов соблюдено не строго. Успешный запуск не означает безошибочность ответа.

Полные ответы и метрики: [`day-26-results.json`](day-26-results.json) (9B), [`day-26-results-4b.json`](day-26-results-4b.json) (4B).

Запуск 9B явно:

```bash
OLLAMA_CHAT_MODEL=qwen3.5:9b npm run llm:local:demo
```

Проверки проекта: `npm run typecheck`, `npm run build` — успешно. Для CLI отдельно проверен простой запрос к 4B.


## Исправление консольного режима

Прежний скрипт скрывал частичный ответ и завершал программу при `done_reason: length`. Теперь ответ выводится потоково, частичный текст сохраняется, достижение лимита не закрывает сеанс. Ошибка отдельного запроса также позволяет задать следующий. Отчёт сохраняется после каждого запроса.

Контекст (вход и ответ) и максимальная длина ответа — разные параметры:

```bash
OLLAMA_CHAT_CONTEXT=32768 OLLAMA_CHAT_MAX_TOKENS=4096 npm run llm:local:chat
```

По умолчанию — 32768 / 4096. Переопределить можно в `.env` или окружении. История по-прежнему не передаётся: каждый вопрос независим.

Повторён вопрос «Объясни разницу между процессом и потоком в ОС. Приведи понятный пример»: полный ответ, 1090 выходных токенов, `done_reason: stop`. При контексте 16K Ollama показал 3,5 ГБ, 100% GPU. При 32K — 3,8 ГБ, 100% GPU. Проверочный вход на 5642 токена обработан за 20,6 с, код из начала текста возвращён правильно. Swap не вырос (около 1,64 ГБ оставалось от предыдущих запусков). Полностью заполненные 16K/32K не проверялись, поэтому комфорт при таком объёме не гарантируется.

Искусственно малый лимит ответа проверен отдельно: два последовательных частичных ответа сохранены, сеанс завершился только по /exit.
