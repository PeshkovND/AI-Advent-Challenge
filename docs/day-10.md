# День 10. Управление контекстом: стратегии

Страница «Стратегии» автоматически отправляет каждый вопрос трём обычным агентам: Sliding Window, Sticky Facts и линейному Branching, чтобы ответы было удобно сопоставлять. На ней Branching не создаёт ответвлений. Страница «Ветки» использует отдельного обычного агента для checkpoint и линий диалога. Состояние каждой стратегии хранится по `agentId` в `data/context-strategies.json` и восстанавливается после перезапуска. Summary используется как отдельная стратегия Дня 9, а не как параллельный механизм агента.

Стратегия задаётся в `AgentConfig.contextStrategy`. Перед отправкой запроса `Agent` обращается к `ContextStrategiesService`, а сервис возвращает подготовленную историю и системный контекст: обрезает окно, обновляет facts, создаёт summary или оставляет линию Branching целиком. Состояние стратегии хранится отдельно по `agentId`, поэтому разные агенты могут использовать разные размеры окна и независимые ветки. Сам `Agent` после этого выполняет LLM-вызов.

## Стратегии

| Стратегия | Контекст основного запроса | Хранение полной истории |
| --- | --- | --- |
| Sliding Window | Последние N сохранённых сообщений + новый вопрос | Да, но сообщения за пределами окна не отправляются модели |
| Sticky Facts | JSON facts + последние N сообщений + новый вопрос | Да, facts и исходные сообщения сохраняются отдельно |
| Branching | Контекст активной линии + новый вопрос | Да, общая часть наследуется только до checkpoint |

N настраивается в карточке конкретной стратегии. Новый вопрос добавляется в запрос отдельно, поэтому не входит в N сохранённых сообщений.

## Sticky Facts

После каждого сообщения пользователя стратегия выполняет отдельный вызов DeepSeek. Он получает только предыдущий JSON facts и новый вопрос, без полной истории, и обязан вернуть JSON с фиксированными ключами:

```json
{
  "goal": [],
  "constraints": [],
  "preferences": [],
  "decisions": [],
  "agreements": [],
  "open_questions": []
}
```

Если facts-вызов или его JSON неуспешен, основной запрос всё равно выполняется с предыдущими facts; интерфейс отмечает предупреждение. Токены facts-вызовов учитываются отдельно и в общем расходе Sticky Facts.

## Branching

На отдельной странице «Ветки» сначала ведите диалог в активной линии. После получения хотя бы одного ответа нажмите «Создать одну ветку из текущей точки». Каждый checkpoint создаёт ровно одну новую линию; можно переключиться на любую линию и создать следующую ветку уже из неё или создать ещё одну линию из той же точки. Новые сообщения веток сохраняются раздельно; при переключении линии соседние решения не попадают в запрос.

Кнопка «Очистить историю» на странице сравнения удаляет историю и состояние трёх агентов сравнения. «Очистить ветки» удаляет историю и линии отдельного Branching-агента, не затрагивая агентов сравнения.

Для всех агентов используются общие endpoint-ы: `POST /api/agents`, `PUT /api/agents/:agentId`, `POST /api/agents/:agentId/run`, `DELETE /api/agents/:agentId/history`, а также `GET /api/agents/:agentId/context`, `POST /api/agents/:agentId/context/reset`, `POST /api/agents/:agentId/context/window`, `POST /api/agents/:agentId/context/checkpoint` и `POST /api/agents/:agentId/context/active-branch`. Последние пять управляют состоянием стратегии только выбранного агента. Экспериментальных маршрутов Day 10 нет.

## Сценарий сравнения

В React-интерфейсе есть модальное окно «Выбрать сообщение» со сценарием Habit Flow. Выбор только подставляет текст в поле ввода: сообщение не отправляется автоматически. Отправка на странице сравнения всегда запускает три стратегии. Кнопки «Показать окно» и «Показать facts» открывают ровно те данные, которые пойдут в следующий основной запрос. На странице Branching создайте несколько линий из разных точек, переключайтесь между ними и проверяйте независимость решений.

Сравнивайте качество, сохранение ранних ограничений, `prompt_tokens`/`total_tokens` и удобство переключения между стратегиями. Для Sliding и Facts размер рабочего окна настраивается в соответствующих карточках.
